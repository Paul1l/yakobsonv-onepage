# YAKOBSON V. — одностраничный сайт

Адаптивный одностраничный сайт Владислава Якобсона по брифу заказчика от 17.10.2026.
Статика без сборки и без внешних CDN: `index.html`, `styles.css`, ES-модули в `js/` (расширение `.js`,
не `.mjs` — на части хостингов `.mjs` отдаётся с неверным MIME), шрифт Inter в `assets/fonts/`.

Сайт не опубликован. `noindex` не стоит намеренно — это сайт, а не тестовая копия.

## Запуск

```sh
py -m http.server 8050 --bind 127.0.0.1 --directory C:\Users\Asus\Desktop\WorkSpace\yakobsonv-onepage
```

Открыть http://127.0.0.1:8050/. Через `file://` модули не загрузятся — нужен любой статический сервер.
`py -m http.server` отдаёт `.woff2` как `application/octet-stream` — браузеры шрифт всё равно применяют;
на хостинге лучше настроить `font/woff2`.

## Проверки

Нужен Node 22+ и установленный Chrome или Edge (headless, без зависимостей — `scripts/lib/cdp.mjs`).

```sh
node scripts/check.mjs          # 75 проверок в браузере; свой сервер на 127.0.0.1:8052, Chrome на порту 9681
node scripts/contrast.mjs       # таблица контраста палитры, падает, если пара ниже нормы
node scripts/screenshots.mjs <папка>   # скриншоты 1440/1024/768/390 (полная страница, разделы, меню); нужен сервер на 8050
```

Переменные: `BASE_URL` — проверить уже запущенный сервер (например, `http://127.0.0.1:8050/`), `CDP_PORT` — порт отладки Chrome.

## Где что менять

| Что | Где |
|---|---|
| Все тексты, показатели ноутбука, направления, CMS, ниши, этапы, контакты | `index.html`, разделы подписаны комментариями `<!-- 1. Шапка -->` … `<!-- 10. Подвал -->` |
| Цвета, отступы, радиусы | `styles.css`, блок `:root` (после правки цвета — `node scripts/contrast.mjs`, значения там же в объекте `C`) |
| Интервал смены ниш (6 с) | `js/niches.js`, `NICHE_INTERVAL` |
| Полный проход точки по этапам (15 с) | `js/process.js`, `PROCESS_PERIOD` |
| Скорость бегущей строки (42 px/с) | `js/marquee.js`, `SPEED` |
| Геометрия карусели (сдвиг, глубина, угол, затемнение) | `js/carousel.js`, функция `cardStyle` |
| Ракурс ноутбука при прокрутке | `js/laptop.js`, `update()`; статичный угол (reduced-motion) — `--rx` в `.laptop` |
| Пункты меню | `index.html`, `<dialog id="site-menu">` |

Новая абстрактная графика направления — inline SVG в карточке; у каждого градиента свой `id` (`g1` … `g9`).

## Решения по неоднозначным местам брифа

- **«Подробнее» в карточке направления** ведёт на `#contacts` (без JS — обычный якорь). С JS над кнопками контактов
  появляется плашка «Направление: …» с кнопкой сброса, а ссылка на почту получает тему письма
  `Обсуждение: …`. Telegram-ссылку не меняем: у личных чатов нет надёжного параметра предзаполнения.
  Новых обещаний и текстов о направлениях не добавлено — в брифе их нет.
- **Две задачи каждой ниши** в брифе не перечислены. Они сформулированы из слов описания ниши
  (например, «Каталоги, таблицы характеристик…» → «Структурировать каталог продукции», «Собрать точные таблицы
  характеристик»). Описание ниши — дословно из брифа. **Задачи нужно подтвердить у заказчика.**
- **Пункт меню «Подход»** ведёт к разделу «От запроса до готовой страницы».
- **Ноутбук:** подписи «Демонстрационные данные» две — плашка на экране и строка под ноутбуком. К показателям добавлены
  поясняющие подписи единиц («визитов в месяц», «запросов», «из визитов в заявки», «за месяц») и период «последние 30 дней»
  в заголовке экрана — это оформление демо-интерфейса, а не новые данные. Десятичная точка (14.2%, 3.4%) — как в брифе.
- **Планшет:** экран содержит только текст, поэтому при наклоне он остаётся доступным скринридеру; устройство не помечено
  `role="img"`. Наклон статичный, при наведении/фокусе устройство мягко выпрямляется.
- **Автосмена ниш** считается на часах requestAnimationFrame (а не setInterval), поэтому сама останавливается
  при скрытой вкладке; дополнительно — по `visibilitychange`, наведению, фокусу, уходу с экрана и паузе.
  Объявления скринридеру — только при ручном переключении (автосмена не «говорит»).
- **Индикаторы карусели на телефоне** (≤ 559 px): девять кнопок в одну строку не помещаются в 44 px шириной,
  поэтому их ширина `min(44px, (100vw − отступы) / 9)` — 31 px на 320, 37 px на 375, 39 px на 390 (высота 44 px).
  Это выше минимума WCAG 2.5.8 (24 px), но ниже 44 px; рядом есть стрелки 48 px и свайп.
- **Без JS:** вся информация видна; карусель — сетка карточек, бегущая строка — статичный список, ниши — все шесть
  по порядку, кнопка «Меню» и кнопки управления скрыты (без скрипта они не работают).

## Что проверено (17.10.2026, `node scripts/check.mjs`, headless Chrome)

Проверено запуском: 75 из 75 проверок (числа — в выводе скрипта):

- перелив `scrollWidth − innerWidth = 0` на 320/375/390/768/1024/1280/1440/1920 (и без JS на 390/1440);
- один H1, уровни заголовков без пропусков; CLS при загрузке 0.0000 на 390 и 1440, Inter загружен;
- меню: открытие, фокус внутри, блок прокрутки колесом, ловушка Tab/Shift+Tab, Esc и «Закрыть» с возвратом фокуса,
  переходы к разделам — заголовок под шапкой, фокус на заголовке;
- карусель: центральная фронтально (`transform: none`), соседняя — `matrix3d`; высота 400 px; стрелки, индикаторы,
  ←/→/Home/End, нажатие на боковую, свайп на 390 (Input.dispatchTouchEvent), вертикальный жест прокручивает страницу;
  в скрытых карточках 0 фокусируемых;
- бегущая строка: движется, пауза кнопкой (aria-pressed), пауза по `visibilitychange` и вне экрана, reduced-motion — стоит;
- ниши: смена через 6006 мс, пауза при наведении/фокусе/вне экрана/паузе/скрытой вкладке, стрелки и индикаторы,
  reduced-motion — без автосмены;
- этапы: полный проход 15.0 с, подсветка совпадает с точкой 7 из 7 замеров, пауза, ручной выбор, скрытая вкладка —
  0 px за 2 с и без прыжка после возврата, вертикаль на 390, reduced-motion;
- ноутбук: ракурс меняется при прокрутке (rotateX 12.5° → 6.2°), мин. кегль на экране 11 px (1440 и 390),
  «Демонстрационные данные» видно, ширина 620 px, раздел не длиннее ~1 экрана;
- без JS весь текст виден; консоль без ошибок и предупреждений во всех прогонах.

Скрытая вкладка в headless не воспроизводится честно: `document.hidden` подменяется в странице и отправляется
настоящее событие `visibilitychange` — проверяется именно реакция кода.

## Не проверено

- Safari (macOS/iOS) и Firefox — только Chrome; на iOS стоит посмотреть 3D-карусель и `backdrop-filter` шапки.
- Реальные устройства и реальные скринридеры (NVDA, VoiceOver) — роли и подписи проверены только по DOM.
- Реальное переключение вкладок и системная настройка «уменьшить движение» — эмулированы.
