# Yakobson V. — одностраничный сайт

Адаптивный одностраничный сайт Владислава Якобсона. Вёрстка и интерактивные блоки — по брифу заказчика от 17.10.2026,
**все тексты и логотип — с основного сайта https://yakobsonv.com/ru/** (снято 19.10.2026).
Статика без сборки и без внешних CDN: `index.html`, `styles.css`, ES-модули в `js/` (расширение `.js`,
не `.mjs` — на части хостингов `.mjs` отдаётся с неверным MIME), шрифт Inter в `assets/fonts/`.

Демо на GitHub Pages: репозиторий https://github.com/Paul1l/yakobsonv-onepage. `noindex` не стоит намеренно — это сайт, а не тестовая копия.

## Темы

Две темы с переключателем в шапке (круглая кнопка рядом с «Меню»: луна/солнце, `aria-label="Тёмная тема"`, `aria-pressed`):

- **светлая** (по умолчанию, в том числе без JS) — палитра демо «Джарвис-гид» https://paul1l.github.io/yakobsonv-navigator-demo/ru/;
- **тёмная** — палитра основного сайта yakobsonv.com, акцент «шампань».

Выбор хранится в `localStorage['yakobson-onepage-theme']`. Тему ставит встроенный скрипт в `<head>` до разбора `<body>` —
вспышки другой темы при перезагрузке нет; `<meta name="theme-color">` обновляется. Системную настройку
`prefers-color-scheme` сайт намеренно не учитывает: по ТЗ по умолчанию светлая.

Все цвета — CSS-переменные в трёх блоках в начале `styles.css`: общее «железо» устройств (корпуса ноутбука и планшета
одинаковые в обеих темах), светлая тема, тёмная тема. Ниже по файлу только `var(--…)`. Экран ноутбука и интерфейс
планшета — в токенах темы: в светлой экран ноутбука светлый, планшет серо-зелёный; в тёмной экран ноутбука тёмный,
планшет — светлая «бумага» в тон шампани. Литералы вне блоков тем: два цвета во встроенном скрипте `<head>` (повторяют `--bg`
тем, нужны до загрузки CSS) и иконки `assets/favicon.svg` / `apple-touch-icon.png` (файлы yakobsonv.com как есть).
Знак логотипа в шапке, меню и подвале — один `<symbol>` в начале `<body>` с `fill="currentColor"`, цвет — `--accent` темы
(бирюзовый в светлой, «шампань» в тёмной), точка в «Yakobson V.» — тоже `--accent`.

## Запуск

```sh
py -m http.server 8050 --bind 127.0.0.1 --directory C:\Users\Asus\Desktop\WorkSpace\yakobsonv-onepage
```

Открыть http://127.0.0.1:8050/. Через `file://` модули не загрузятся — нужен любой статический сервер.
`py -m http.server` отдаёт `.woff2` как `application/octet-stream` — браузеры шрифт всё равно применяют;
на хостинге лучше настроить `font/woff2`.

## Проверки

Нужен Node 22+ и установленный Chrome или Edge (headless, без зависимостей — `scripts/lib/cdp.mjs`).

```sh
node scripts/check.mjs                  # обе темы + переключатель: 177 проверок; свой сервер 127.0.0.1:8052, Chrome на 9681 (~7 мин)
node scripts/check.mjs --theme=dark     # одна тема (light | dark) + переключатель: 93 проверки
node scripts/contrast.mjs [--md]        # контраст обеих тем, значения читает из styles.css; падает, если пара ниже нормы
node scripts/screenshots.mjs <папка> [--theme=both] [--widths=1440,1024,768,390]   # нужен сервер на 8050
```

Переменные: `BASE_URL` — проверить уже запущенный сервер (например, `http://127.0.0.1:8050/`), `CDP_PORT` — порт отладки Chrome.

## Решения по неоднозначным местам брифа

- **«Подробнее» в карточке направления** ведёт на описание направления на yakobsonv.com (`/ru/services/#sites` и т. д. —
  те же якоря, что у карточек на главной). Подробностей направлений на одностраничнике нет. Прежняя подстановка темы письма
  («Направление: …», `js/contacts.js`) убрана вместе с переходом «Подробнее» → контакты.
- **Задачи ниш** («две задачи», придуманные по брифу) убраны: на yakobsonv.com у ниши есть только название и описание —
  они и стоят в планшете. Свободное место в слайде занимает декоративный номер ниши (скрыт от скринридера).
- **Формы нет.** На yakobsonv.com разбор заказывают формой «Адрес вашего сайта → Получить разбор»; у статичного сайта на
  GitHub Pages нет сервера, а форма, которая показывает «отправлено» без сервера, запрещена правилами проекта. В разделе
  «Контакты» текст блока разбора дословно, а вместо формы — «Написать в Telegram», «Написать на email · yakobsonv@icloud.com»
  и «Получить разбор · yakobsonv.com» (ссылка на форму `/ru/#audit`).
- **Проверка сайта (Lighthouse)** работает только на yakobsonv.com (нужен сервер). Здесь — тексты блока и кнопка «Проверить»,
  которая открывает главную yakobsonv.com; поля ввода и результатов нет.
- **Ноутбук:** превью дашборда как на yakobsonv.com — 5 вкладок (Обзор, Позиции, Трафик, Контент, Задачи) со всеми подписями
  и цифрами сайта. Кнопки вкладок стоят под ноутбуком: на экране нет места для целей 44 px. На экране — плашка «Sample»,
  под ноутбуком — «Демонстрационные данные. …». На 1440 все вкладки помещаются в экран без прокрутки; на телефоне «Обзор»
  помещается целиком, остальные вкладки прокручиваются внутри экрана (панель фокусируется с клавиатуры, `tabindex="0"`).
  Без JS кнопки вкладок скрыты, а все пять панелей идут на экране подряд. Заголовки столбцов «Страница / Визиты / Рост»
  у таблицы «Топ страницы по росту» — только для скринридера (на сайте их нет).
- **«Кто работает»:** на главной об основателе — одна строка («Разбор делает и отвечает лично…», она есть в контактах).
  Раздел заполнен блоком «Кто работает» со страницы «О компании» дословно, со ссылкой на неё.
- **Строчные ссылки в тексте** («статье про процесс», «Аудит», «тарифах», «Напишите») — класс `.text-link`; проверка размера
  цели их не считает: исключение WCAG 2.5.8 для ссылок внутри предложения.
- **Планшет:** экран содержит только текст, поэтому при наклоне он остаётся доступным скринридеру; устройство не помечено
  `role="img"`. Наклон статичный, при наведении/фокусе устройство мягко выпрямляется.
- **Автосмена ниш** считается на часах requestAnimationFrame (а не setInterval), поэтому сама останавливается
  при скрытой вкладке; дополнительно — по `visibilitychange`, наведению, фокусу, уходу с экрана и паузе.
  Объявления скринридеру — только при ручном переключении (автосмена не «говорит»).
- **Пропорции ноутбука на телефоне.** Экран держит пропорцию строго (интерфейс `.dash` лежит поверх, `inset: 0`):
  16:10 от ~676 px окна, 3:2 на телефоне (≤ 559 px). На узком экране (контейнер ≤ 575 px) интерфейс перекладывается,
  а не уменьшается: четыре показателя — лента со свайпом (видны две карточки и край третьей), таблица без переносов,
  кегль ≥ 11 px. Если текст всё же не влез (320 px, увеличенный шрифт), он прокручивается внутри экрана.
- **Планшет на телефоне** (≤ 559 px) стоит вертикально, 3:4, ширина до 320 px; от 560 px — горизонтальный 4:3.
- **Индикаторы карусели на телефоне** (≤ 559 px): ряд выходит за поля на всю ширину окна, точки делят её поровну
  (до 48 px), высота 48 px — ≈ 36 px на 320, 42 на 375, 43 на 390, 48 на 430. Девять целей по 44 px в 390 px
  не помещаются физически; это выше минимума WCAG 2.5.8 (24 px), рядом есть стрелки 48 px и свайп.
- **Без JS:** вся информация видна; карусель — сетка карточек, бегущая строка — статичный список, ниши — все шесть
  по порядку, дашборд — все пять вкладок подряд на экране; кнопка «Меню», вкладки и кнопки управления скрыты (без скрипта они не работают).
